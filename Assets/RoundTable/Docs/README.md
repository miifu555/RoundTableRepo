# Round Table（円卓カードゲーム）実装メモ

Notion の仕様書「Round Table(円卓カードゲーム)」を Unity で動くようにしたものです。

- **CPU対戦**（1人用・強さ3段階）/ **ホットシート**（同じPCで2人交代）/ **通信対戦**（GitHub経由）の3モード
- BGM 2種・効果音6種つき（すべて `Tools/make_audio.py` で合成。外部素材なし）
- カードは**1枚 = 1プレハブ**。効果も絵も Inspector から個別に編集できる
- UI は**シーンに実体で置いてある**（実行時に生成しない）ので、位置や色は手で動かせる

## 起動

`Assets/RoundTable/Scenes/01_Title.unity` を開いて Play。
Build Settings には 01→02→03 の順で登録済みです。

| シーン | 役割 |
|---|---|
| `01_Title.unity` | タイトル / 対戦モードの選択（CPU・ホットシート・通信）/ CPUの強さ / 通信設定の入力 |
| `02_DeckSelect.unity` | キャラ（デッキ）の選択、デッキ内容の確認 |
| `03_Battle.unity` | 対戦画面 |

## エディタメニュー

| メニュー | 内容 |
|---|---|
| **Round Table / すべて再生成** | カードプレハブ・デッキアセット・3シーンを作り直す。割り当て済みの絵と Inspector で変えた効果は引き継がれ、**レイアウトだけ**作り直される |
| **Round Table / 通信トークンを設定** | 通信対戦の共有トークンをビルドに焼き込む/解除する。焼き込むとプレイヤーはトークン入力不要になる |
| **Round Table / WebGL をビルド** | ブラウザで遊べる形に書き出す（出力先 `Build/WebGL`、詳細は `Build.md`） |
| **Round Table / デッキ構成を検証** | 全11デッキが15枚になっているか点検する |
| **Round Table / イラストを一括割り当て** | `Art/` 以下の PNG をファイル名でカード・デッキ・データベースに割り当てる |
| **Round Table / 割り当て状況を確認** | まだ絵が入っていないものを Console に一覧表示 |

通常の編集で「すべて再生成」を実行する必要はありません。プレハブとシーンを直接いじってください。

## カードを編集する

`Prefabs/Cards/{デッキID}/{カードID}.prefab` を選び、Inspector の **Card Data** を編集します。

| 項目 | 意味 |
|---|---|
| Display Name | カード名（仕様書で未確定だったものは仮称） |
| Kind | 攻撃 / フィールド |
| Cost | 消費する気力 |
| Effect Text | カードに印刷される文章（表示専用） |
| Trigger | フィールドの発動タイミング。攻撃カードと常在効果は None |
| Effect / Amount / Dice Sides / Modifier | 実際の挙動 |
| Illustration | カード枠内のイラスト（440×330） |
| Full Card Image | カード全体を1枚絵で差し替える場合（500×700） |

**効果テキストと実際の挙動は別物**です。文章だけ変えても挙動は変わりません（逆も同じ）。

カードの見た目そのもの（枠の色、文字サイズ、配置）を全カード一括で変えたい場合は
`Prefabs/Cards/_Base/Card.prefab` を編集すれば、59枚すべてに反映されます。

## デッキ構成を編集する

`Data/Decks/{deckId}.asset` を選ぶと専用の編集画面が出ます。
**カードの種類と枚数はここで管理**します（枚数はカード側ではなくデッキ側が持っています）。

- 合計が常に「◯ / 15 枚」で表示され、ズレていれば赤くなる
- `−` `＋` と数値入力で枚数を増減、`▲▼` で並べ替え、`×` で除外
- 下の枠にカードのプレハブをドロップすると追加
- 仕様書と枚数が違う行には `*` が付く
- **「このデッキのフォルダから全カードを追加」/「枚数を仕様書の値に戻す」** ボタンあり

メニュー **「Round Table / デッキ構成を検証」** で全11デッキをまとめて点検できます。

> 「すべて再生成」しても、**手で変えた枚数は引き継がれます**。
> 仕様書側（`CardSeedData.cs`）の枚数が変わった場合は新しい値に従います
> （`DeckEntry.SpecCount` に仕様書の値を控えて区別しています）。

## CPU対戦

タイトル画面の「CPUと対戦」から。強さは **よわい / ふつう / つよい** の3段階です。

| 強さ | 挙動 |
|---|---|
| よわい | だいたい最善手だが、45%の確率でわざと別の手を選ぶ |
| ふつう | 評価値が一番高い手を出す |
| つよい | ふつうと同じ思考に加え、壊すフィールドの選び方が丁寧（継続効果を優先して壊す） |

思考の中身は `Scripts/App/SimpleAi.cs`。1回の呼び出しで操作を1つ返すだけの単純な評価関数です。

- ダメージは「軽減後の実ダメージ × 12」。**相手を倒しきれる手は最優先**
- 山札を削り切れる（デッキアウトさせられる）手も最優先
- コスト支払いで自分の気力が0になる手は、**決定打でない限り打たない**（自爆回避）
- 同名のフィールドを並べ過ぎないように減点

CPUの手番の待ち時間は `MatchController.AiThinkSeconds`（既定 0.6秒）で変えられます。
AIが返すのは通信対戦とまったく同じ操作コードなので、適用の経路は人間の操作と共通です。

## 仕様書どおりに実装した部分

- 気力10スタート、カード使用でコストとして消費、自分のターンが返ってくると10に回復
- 攻撃カード＝即時発動 / フィールドカード＝場に何枚でも置ける
- ドロータイプ＝ターン開始時に1枚
- シャッフルタイプ＝ターン開始時に**手札ごと山に戻してシャッフルし、4枚引く**（手札を抱え込めない）
- ざきの《便乗》は「相手が**攻撃カードの効果で**ドローしたとき」だけ誘発する
  （番の始まりの通常ドローやフィールドの誘発ドローでは反応しない）
- 使ったカードは一時的にトラッシュへ行き、ターンが返ってきてカードを引く前に**使用順で山の下**へ戻る
- 相手の気力を削り切ると ^^（だお）を獲得
- コストの使い過ぎで自分の気力が0になると自爆し、相手に ^^ が入る
- ^^ を3つ集めたプレイヤーの勝利
- デッキはカスタム不能、1デッキ15枚（11デッキすべて15枚であることを検証済み）

## 仕様書に書かれていなかったので補完した部分

| # | 補完した内容 | 理由 / 場所 |
|---|---|---|
| 1 | 初手手札は**ドロータイプ4枚・シャッフルタイプ0枚** | シャッフルタイプは自分の番の頭で手札を捨てて4枚引き直すため、初手を配る意味がない。`RoundTableGame.DrawTypeOpeningHand` |
| 2 | 「トラッシュ」を2種類に分けた | `PendingReturn`（使用カード・破壊されたフィールド・手札から捨てたカード → 次の自分のターンに山の下へ）と `Trash`（**山札削りだけ**・完全消滅）。こうしないと奥野の LO が成立しない |
| 3 | 山札が尽きて引けなくなったら相手に ^^ | 奥野が LO デッキとして定義されているため |
| 4 | 「気力を削られた時」はコスト支払いでは誘発しない | 誘発すると自分のコスト支払いで相手の盤面を壊せてしまう |
| 5 | 「**カードで**気力を削られたとき」は攻撃カードの解決によるダメージのみ | 「気力を削られた時」との書き分けを尊重 |
| 6 | 軽減でダメージが0になった場合は「削られた」扱いにしない | |
| 7 | 「相手の気力の最大値を1減らす」は**回復時の上限にだけ**効く | 設置した瞬間に相手を即死させないため |
| 8 | あぽろ《抜き取り》の手札トラッシュ2枚は**ランダム** | 相手の手札は非公開のため |
| 9 | 「番の終わり」＝**自分のターンの終わり** | とーしー《一息つく》 |
| 10 | 誘発効果によるフィールド破壊の対象は**自動選択**（コスト最大） | 手動選択は「自分が出した攻撃カード」の破壊のみ |
| 11 | 先攻はラウンドごとに交代（初回はランダム） | |
| 12 | **1ラウンド60手番で引き分け、両者に ^^ が1つ入る** | ★下記。`RoundTableGame.RoundTurnLimit` |
| 13 | 誘発の相互ループは深さ32で打ち切り | ざき×すどーの「削られた時に削り返す」同士など |

### ★ 12 について（仕様の穴）

使ったカードは山に戻るのでデッキが尽きません。そのため

- とーしーの《鉄壁の言い訳》（削られる気力 -1）が3枚並ぶ
- 相手の攻撃が3ダメージ以下しかない

この条件が揃うと**どちらも永久にダメージを与えられません**（とーしー同士のミラーで実際に確認）。
仕様書に千日手の規定が無いので、ハウスルールとして
「60手番でそのラウンドは引き分け・両者に ^^ が1つ入る」を入れて必ず決着するようにしています。
不要なら `RoundTableGame.RoundTurnLimit` を大きくしてください。

## 画面のアスペクト比

**16:9 (1920×1080) に固定**。ウィンドウの比率が違う場合は黒帯が出て、レイアウトは崩れません。

- `CanvasScaler` を `ScreenMatchMode.Expand`（拡大率 = `min(画面幅/1920, 画面高/1080)`）
- Canvas 直下に **1920×1080 ちょうどの `SafeArea`** を中央配置、`RectMask2D` ではみ出しを防止
- その背面に黒い全面 Image（`Letterbox`）

固定をやめたい場合は各シーンの CanvasScaler を `MatchWidthOrHeight` に変え、
`SafeArea` のアンカーを全面ストレッチにしてください。

ビルド時のデフォルトウィンドウは 1600×900（16:9）／リサイズ可に設定済みです。

## フォント

`Assets/SU3DJPFont` の **mplus-1p-medium SDF Dynamic** を使っています。
変更するなら `RoundTableBuilder.FontPath` を書き換えて「すべて再生成」するか、
各 TextMeshPro コンポーネントの Font Asset を差し替えてください。

> TextMeshPro の Overflow を `Truncate` にすると、1行の高さが枠に収まらないとき
> **行ごと消えます**（最初にタイトル文字が出なかった原因がこれ）。
> `UiBuilder` では既定を `Overflow` にし、枠から溢れては困る箇所
> （カードの効果テキスト等）だけ `Truncate` にしています。

## 通信対戦

`Docs/Online.md` を参照。要点だけ:

- 郵便受けに使うリポジトリは **`miifu555/RoundTableLobby` に固定**（`OnlineConfig.FixedOwner` ほか）。
  プレイヤーが入力するのは**アクセストークンと部屋名とホスト/ゲストの3つだけ**
- トークンは「Round Table / 通信トークンを設定」でビルドに焼き込める。焼き込むと**部屋名とホストON/OFFだけ**になる
  （焼き込みファイルは `.gitignore` 済み。ビルドから取り出せる点は割り切り）
- GitHub のリポジトリを郵便受けにして、**操作ログだけ**をやり取りする
- ルールエンジンがシード固定で決定論的なので、盤面そのものは送らなくてよい
- 自分は自分のファイルだけ書き、相手のファイルだけ読むので**書き込み衝突が起きない**
- 反映まで2〜4秒。ターン制なので実用範囲
- トークンは PlayerPrefs に平文保存。**第三者に配布するビルドには入れないこと**

### 今回のルール変更の影響

**シャッフルタイプが「手札ごと山に戻して4枚引き直す」**に変わり、手札を抱え込めなくなりました。
該当は 鈴木・奥野・しょー・こうの・りくと・没ステ の6デッキです。
勝率への影響は思ったより小さく、こうの +5.0 / りくと +2.0 に対し 奥野 -3.7 / しょー -3.8 と割れました。
高コストのカードを溜めて撃つ動きが消えたぶん、安いカードを並べるデッキが得をしています。

**ざきが 43.8% → 60.0% と大きく伸びました。** 《意趣返し》がコスト1になり、
「削られたら2削り返す」を序盤から並べられるようになったのが効いています。
あぽろ戦だけは 21% と苦手ですが、それ以外はほぼ五分以上です。

**すどーが -7.9pt。** 《全身全霊》は手札の枚数がそのまま火力になるので、
相手のシャッフルタイプが毎ターン手札を撃ち切ってくるようになった影響を受けています。

### まだ気になるところ

- **没ステが 15.0% で単独最下位のまま**。今回も変更がなく、相性表では かっしーに0%、すどーに0%、とーしーに8%。
  コスト3のフィールドを並べる時間が無いのが一貫した原因です
- **しょーが 35.4% で下から2番目**。《先制攻撃》の2ダメージは強いのですが、
  シャッフルタイプになったことで毎ターン手札が流れ、連撃が続きません
- 上位は かっしー 69.2% で据え置き。ここを下げるなら《タックル》か《大振り》です

数値を変えたら「すべて再生成」→ 総当たりを回し直せば、この表はすぐ更新できます。
CPU同士の結果なので、人間が回せばまた別の数字になります。あくまで目安として。
